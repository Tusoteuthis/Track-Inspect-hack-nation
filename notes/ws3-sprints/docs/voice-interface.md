# WS3 → WS5 (and WS6/WS7): voice component and expert-session output

**Status:** Sprint 4 (2026-10-04), final WS3 interface. Contracts: `docs/contracts-v0.md` (ws3.v1). Trust rules: `docs/trust.md`.

## 1. Reusing the voice component

`web/components/voice/VoiceSession.tsx` wraps the ElevenLabs `ConversationProvider` (WebRTC) with a start/stop orb and a live transcript. It knows nothing about the expert flow; the expert flow is just one set of props.

```tsx
<VoiceSession flow="tutor" {...tutorProps}>
  <TutorPanel />   {/* rendered inside the provider: may call useConversationControls() */}
</VoiceSession>
```

| Prop | Use |
|---|---|
| `flow` | Key in `web/lib/voice/flows.ts`; selects the agent through the token route |
| `dynamicVariables` | Values for `{{placeholders}}` in the agent's prompt / first message |
| `clientTools` | `Record<name, (params) => string \| number \| void \| Promise<…>>`; names must match the agent's client tools. The returned string goes back to the LLM |
| `onFinalLine(line)` | Once per final transcript line (`{id, role, text, at}`) |
| `onConnected(conversationId)` | After connect; keep the id (needed for history/deletion) |
| `onAgentModeChange("speaking"\|"listening")`, `onDisconnected()` | Turn and lifecycle |
| `onVadScore`, `onUserTentative` | Speech signals (need `vad_score`, `tentative_user_transcript` client events on the agent) |
| `onStop()`, `onSessionError(message)` *(Sprint 4)* | Tell a Stop from a dropped connection or an error |
| `children` | Inside the provider: `useConversationControls()` gives `sendContextualUpdate(text, {contextId})`, `sendUserMessage`, `sendUserActivity`, `getInputVolume`; `useConversationInput()` gives `setMuted` |

**Patterns that worked for us (keep them):**
- **Client tools that return results** (`expectsResponse: true`, `executionMode: "immediate"`, `preToolSpeech: "off"`). The client is the authority: it validates params, assigns ids and answers with `ok …` / `error …` text the agent acts on. Keep the reducer in a ref so tools captured at connect see the latest state (`useExpertSession.ts`).
- **Contextual updates don't trigger a turn** (VERIFIED LIVE). Use them for state (`contextId` per kind, so a newer update supersedes the older one); send one `[CONTROL] …` user message when the agent must speak now, and filter `[CONTROL]` lines out of the human's transcript (`isControlText`).
- **Never send the API key to the browser.** The browser calls `GET /api/conversation-token?flow=<flow>` (`web/app/api/conversation-token/route.ts`) for a short-lived WebRTC token.

**Adding the tutor flow:** `flows.ts` already has `tutor: { envVars: ["ELEVENLABS_AGENT_ID_TUTOR"] }`. Put the tutor's prompt, first message and `tools.json` under `agents/tutor/`, add it to `agents/manifest.json` (same shape as `expert`), then:

```bash
cd web
npm run sync-agents -- --agent tutor     # pushes prompt, first message, tools (upserted by name), settings
npm run probe -- tutor --runs 5          # text simulations from agents/probes.json "tutor" cases; report ≥ 4/5
```

Probe cases can replay tool calls (`{"role":"agent","tool":{name,params,result}}`), mock tool results per agent (`toolMocks`) or per case (Sprint 4), and assert with `requireTools`, `forbidTools`, `forbidPatterns`, `requirePatterns`, `requireReply`, `maxQuestions`, `maxWords`, `endsWithQuestion` (see `web/scripts/probe-agents.mts`). Keep probe system lines and tool results generated by the app (`probe-lines.ts` + `probes.test.ts`), or the probes drift from what the app sends. Never sync or probe an agent that is not yours.

## 2. What an expert session writes (consume these)

`knowledge/sessions/<session_id>/` (root `KNOWLEDGE_DIR`, default `<repo>/knowledge`; WS6 may move it behind its backend):

| File | Meaning for WS5 |
|---|---|
| `knowledge-draft.md` | **The WS5-facing view.** Latest revision; per step: kind, verification (`confirmed` / `unresolved`), screen moments (highlighted + full-frame images, FIXTURE-labelled) and the expert's verbatim answers; guardrails, open questions, diff to the parent, confirmations (struck ones marked invalidated), excluded material (neutral markers) |
| `revisions/rev-N.json` | Immutable `DraftRevision`s (`steps[]` with `supporting_event_ids`, `supporting_exchange_ids`, `supported`; `parent_revision_id`, `change_reason`, `change_exchange_ids`). Rewritten only to redact a revision a strike superseded |
| `confirmations.json` | `ExpertConfirmation[]`: exact `revision_id`, `status` (`confirmed`/`corrected`/`unresolved`), `step_ids_reviewed`, `expert_response_exchange_id`. Check `session.json.strikes[].invalidated_confirmation_ids`: those no longer count |
| `exchanges.json` | `ExpertExchange[]`: question (verbatim), `answer_lines[]` (expert words, verbatim, never edited), `event_id`, `related_event_ids`, `phase`, `kind`, `gap_id`, `revision_id`, `source`. A struck exchange has `answer_lines: []` |
| `events.json` | On-record `PointingEvent`s only (images: `image_ref`, `highlighted_image_ref`) |
| `session.json` | Everything else (topics, coverage, open questions, agenda, revisions, confirmations, recording segments, strikes, deletion reports) + derived `counts` |
| `completion.json` / `.md` | `SessionCompletion`: end reason, `confirmed_revision_id`, unfinished items, unresolved questions, excluded counts, question counts (written once the session ended) |
| `demo-evidence.md` | Challenge checklist, annotated transcript, timing, live vs fixture |
| `transcript.md`, `exchanges.md`, `timing-report.md`, `timing.json`, `elevenlabs-deletion.json` | Evidence / debugging |

**Eligibility rule (teaching material):** only steps whose verification is `confirmed` in the **latest** revision, and only if that revision has an explicit, non-invalidated `confirmed` confirmation and is not superseded (`completion.json.confirmed_revision_id` names it; it is null otherwise). Concretely, use `stepVerification(revisions, activeConfirmations(snapshot))` from `web/lib/expert/draft.ts`, or `completion.json`. `unresolved` steps, unsupported steps and open questions are not facts. A `corrected` revision is never teaching material; its successor is. **Off-record content is absent by construction** (never stored; the validator refuses it), and struck words are removed, so nothing extra must be filtered — but WS5's own `eligibility.ts` (`off_record_evidence`, `superseded`) is a welcome second guard.

Quotes: anything in quotation marks inside step text must appear verbatim in the linked `answer_lines` (`checkQuotes`); step text itself is AI synthesis.

## 3. Replacing WS3's synthesis

`web/lib/expert/synthesis.ts` is the swap point:

```ts
interface Synthesis {
  getGaps(state: SynthesisState): Gap[];                       // ordered; covered items never appear
  buildDraft(state, parent: DraftRevision | null, options: {
    proposal: ProposeDraftParams | null; at_utc: string; change_reason: string | null; change_exchange_ids: string[];
  }): BuildResult;                                              // next immutable revision, or errors
}
```

`SynthesisState` = `session_id, events, exchanges, topics, coverage, open_questions, revisions` of the snapshot — already free of off-record and struck content. Keep the evidence ids (`event_id`, `exchange_id`) as they are; leave revision and step ids to `buildRevision` (stable `s-N` across revisions); keep the verbatim-quote check. The debrief agenda is frozen at debrief start (top 5 gaps); the agent asks only those (`begin_question` with `gap_id`).

## 4. Session lifecycle notes for WS6/WS7

- The client PUTs the whole snapshot (`PUT /api/expert-sessions/<id>/snapshot`), debounced; saves are idempotent. The session id is minted client-side (`ses-<yyyymmdd>-<hhmmss>-<rand4>`).
- `phase`: `live → debrief → teach_back → confirmed`, or `incomplete` at the end. **Resume (best effort):** after an unconfirmed end, "Resume this session" + Start reopens the same session id in its previous phase with a new conversation (`conversation_ids` grows) and sends a `[RESUME]` state summary (ids, phase, open gaps, revision status — never the transcript). The agent greets again (first message cannot be overridden without enabling overrides on the agent) and has no memory of the earlier conversation beyond that summary.
- Show the record state from `recording_segments.at(-1)` (acknowledged), and the ElevenLabs deletion result from `elevenlabs_deletions` — never from a local toggle.
- Routes: `POST …/elevenlabs-deletion` (session-scoped), `POST …/demo-evidence` (re-derived from disk).
