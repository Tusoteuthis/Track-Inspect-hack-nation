## Delivered

**Contracts**
- `web/lib/contracts/`: versioned transport contracts `ws6.v0`. Each resource has a zod schema, an inferred type and a `parseX()` that returns `ParseResult` (`{ok,value}` or `{ok:false,error:{code:"validation_failed",issues[]}}`). Client-safe: no `node:` imports.
  - `expert.ts` re-exports the WS3 types from `@/lib/expert/contracts` and wraps them in zod. Compile-time equality checks break typecheck if WS3 changes a shape.
  - Ingest extensions: `PointingEventIngestSchema` (+`asset_id?`) and `ExpertExchangeIngestSchema` (+`rev?`).
  - `session.ts`, `asset.ts`, `knowledge.ts` (KnowledgeEntry, KnowledgeRevision, Confirmation, `toConfirmation`), `learner.ts` (LearnerDraft, Evaluation, Commit), `assessment.ts`, `bus.ts` (strict, IDs only), `errors.ts` (ErrorCode, ERROR_STATUS, ApiErrorBody), `common.ts`, `parse.ts`, `version.ts`, `index.ts`.

**Backend primitives**
- `web/lib/backend/config.ts`: `getConfig()` returns `{knowledgeDir, runtimeDir, evaluatorDir}`. Defaults are `<web>/../knowledge`, `<web>/.runtime` and `<runtime>/evaluator`; env overrides apply. Tests use `setConfigForTests` / `resetConfig`.
- `web/lib/backend/ids.ts`: `ID_RE`, `isValidId`, `assertSafeId`, `newId(prefix)` (`ses|cnf|evl|cmt|rev`-yyyymmddhhmmss-rand6) and `safeJoin`. A doc comment states the idempotency rule.
- `web/lib/backend/store.ts`: `writeFileAtomic`, `writeJsonAtomic`, `readJson`, `canonicalJson`, `putImmutable` and `putMutable` (`rev`, or `revOf` for `draft_rev`).
- `web/lib/backend/locks.ts`: `withLock(key, fn)`, a per-key in-process mutex. It assumes a single process (documented).
- `web/lib/backend/errors.ts`: `ApiError` and `toErrorResponse`. Unknown errors become 500 `internal` and never echo their message. Codes come from `@/lib/contracts`.

**Health route**
- `web/lib/backend/health.ts` and `web/app/api/health/route.ts`: `GET /api/health`. Returns 200, or 503 if a data directory is not writable.

**Fixtures**
- `web/fixtures/ws6/`: 20 labelled JSON fixtures plus `knowledge-revision.md`, two placeholder PNGs (each with a FIXTURE text chunk) and a README. All use `source:"fixture"` and `fixture-session-001`, with neutral text only. The PNGs are generated by `web/scripts/make-fixture-pngs.mts`.

## Decisions made

1. **`voice` merge.** It was first skipped, because `voice` at `44f5489` was a WIP commit that tracked worktree gitlinks. Once `voice` had moved to `4aaa20c` (cleaned in `ef80cfb`, with WS3 S0 and WS7 S0 merged), the human approved merging it. The feature branch was then recreated on the merged base.
2. **WS3 types are re-exported and wrapped, not forked.** WS6 ID fields are stricter (`^[a-z0-9][a-z0-9-]{0,63}$`) than WS3's "non-empty string". `trace_id` and `channel_id` stay free strings.
3. **Confirmation naming.** WS6 `Confirmation` uses `reviewed_revision_id` and `result`, as the prompt specifies. WS3's `ExpertConfirmation` (`revision_id`, `status`) is accepted and mapped by `toConfirmation()`.
4. **`KnowledgeRevision.revision_id` is globally unique** (`rev-<time>-<rand>`). A separate `revision_no` names the file `rev-<n>.md`, so confirmations, pins and citations need no `entry_id`.
5. **`putMutable` with an equal rev and identical body** returns 200 as an idempotent retry. An equal rev with a different body is rejected (research R6).
6. **Evaluation and Assessment extras.** WS5's optional fields (`cited[].quote`, `guiding_question`, `escalation`, and the opaque `content` on Assessment) are accepted. `outcome` remains an opaque string.
7. **Health** returns 503 with `ok:false` when a data directory is not writable (the prompt only specified the 200 case).
8. **Lane B validation rules** (stricter than data-model.md):
   - an expert Session must have `pinned_knowledge: null`, so extensions of `SessionSchema` need `.safeExtend()`
   - `BusEvent.type` must be dotted lowercase
   - `content_path` must be relative with no `..`
   - `AssetFile.path` must be a bare filename
9. **The API doc departs from the S1/S3 prompts.** These changes keep error codes consistent; check them at the gate.
   - **D7:** a stale exchange write returns `409 stale_revision`. The S1 prompt said `200 ignored_stale`.
   - **D8:** an off-record content write returns `403 off_record`. The S1 prompt said `409`.
   - **D9:** SSE events are renamed to a single scheme (`confirmation.stored`, `evaluation.updated`, `commit.stored`).
   - **D10:** commit-guard reasons map to `evaluation_stale`, or to `commit_blocked` + `details.reason`.
   - **D11:** one confirmation POST covering N revisions stores N `Confirmation` records.

   The S1 and S3 prompt files have not been edited. Each of those sprints should follow `ws6-api-v0.md` once you approve it.
10. **Gitignore.** `knowledge/learner/` and `knowledge/confirmations/` are ignored as runtime data. Only `knowledge/workflow.md` and `knowledge/entries/` remain committable.

## Known limitations / open issues

- **Single process.** The in-memory locks, and the SSE bus that comes later, assume one `next dev` / `next start` process.
- **Two vitest configs in `web/`.** WS3's `vitest.config.mts` and WS7's `vitest.config.ts` both exist; vitest uses the `.ts` one. WS6 adds neither.
- **Shared session ID.** `fixtures/ws6/session.json` (expert) and `session-newcomer.json` both use `fixture-session-001`, as the prompt requires. They are alternative shapes and are never stored together.
- **npm audit** reports 3 vulnerabilities (2 high, 1 critical). They come from existing dependencies; WS6 has not investigated them.
- **The constitution** is now 1.1.0. If WS3 amends it in parallel, a merge conflict is limited to:
  - one added line in the Sync Impact comment
  - the `**Version**` footer line
  - the section inserted before `## Governance`
