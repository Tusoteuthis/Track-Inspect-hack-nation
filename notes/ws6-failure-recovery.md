# WS6 failure and recovery notes

Where to look first:
- `GET /api/health` → `failing_components` and `components.<name>.last_error`.
- `/diagnostics` in the browser (or `GET /api/diagnostics?session_id=<sid>`) → the session's ID chain and its diag timeline.

Diagnostics hold IDs, timings and error codes only, never content. The raw log is `web/.runtime/diag/<date>.ndjson` (one line per request or job: `component`, `op`, `ids`, `outcome`, `duration_ms`, `error_code`).

`npm run e2e` prints which step failed and why, e.g. `step "synthesis" aborted — backend unreachable … (ECONNREFUSED)`.

| Component | Symptom | How diagnostics show it | Recovery |
|---|---|---|---|
| **Backend down / wrong port** | UI shows "disconnected"; the iPhone or scripts get connection errors | `npm run e2e` reports `backend unreachable … (ECONNREFUSED)` with the step name; `/diagnostics` says "The backend did not answer" | Start `npm run dev -- -p 3006` (add `-H 0.0.0.0` for LAN). Port taken: `lsof -i :3006`, then stop the other process. |
| **Storage not writable** | Every write fails with `500 internal` | `/api/health` → `503`, `knowledge_dir_writable: false` or `runtime_dir_writable: false` | Fix the permissions or the paths (`KNOWLEDGE_DIR`, `RUNTIME_DIR`); check free disk space. |
| **ElevenLabs token failure** | The voice session does not start; `/api/conversation-token` returns 4xx/5xx | `/api/health.elevenlabs` shows which of `api_key_configured`, `expert_agent_configured`, `tutor_agent_configured` is `false`; `components.voice.last_error` shows the last error code (op `conversation-token`) | Put `ELEVENLABS_API_KEY` and the agent IDs in `web/.env` and restart. A `409 invalid_transition` with `session_id` means the session is not `active`: `POST …/lifecycle {action:"start"}` first. If the key is set but tokens fail, check the key/plan in the ElevenLabs dashboard (`npm run probe`). |
| **iPhone can't reach the laptop** | The phone's requests time out | No diag lines appear for `assets`/`events` while the phone is "sending" | Start with `-H 0.0.0.0`. Check the IP (`ipconfig getifaddr en0`) and open `http://<ip>:3006/api/health` in the phone's browser. Put both devices on the same Wi-Fi with no guest/client isolation. Allow incoming connections for `node` in the macOS firewall. With `BACKEND_ACCESS_TOKEN` set, the app must send `Authorization: Bearer <token>` (otherwise `401 unauthorized`). |
| **Upload rejected** | The asset PUT returns 4xx | `components.assets.last_error.error_code`, and the response body's `error.code` / `details` | `validation_failed`: `details.field` names the problem (not PNG/JPEG, declared size ≠ image, over `ASSET_MAX_BYTES`, missing `meta`). `conflict_immutable`: the same `asset_id` with different bytes, so use a new ID. `gone` (410): the asset was deleted, so use a new ID. `202 dropped_off_record` is **not** an error: the session (or the capture time) was off the record, so nothing was stored. An event whose asset is missing → `409 asset_not_available`: upload the asset first. |
| **Synthesis failed** | No new draft or revisions after `POST …/synthesis`; SSE `synthesis.failed` | `GET /api/jobs/<job_id>` → `status: failed`, `error.code` (`module_error`, `invalid_output`, `dangling_reference`, `revision_conflict`, `interrupted`, `internal`); `failing_components` contains `synthesis` | `module_error`: the WS5 module threw; try `WS5_MODULES=stub` to confirm the backend path works, then report to WS5 with the job ID. `interrupted`: the server restarted mid-job, so re-run. `revision_conflict`: knowledge changed underneath, so re-run. |
| **Synthesis discarded** | SSE `synthesis.discarded`; no revisions | The job's `discard_reason`: `exchange_changed:<id>`, `event_deleted:<id>`, `entry_changed:<id>`, `confirmations_changed`, `generation_changed:a->b` (a deletion or off-record purge happened during the run) | Expected behaviour: old work never overwrites new state. Re-run synthesis on the current inputs. |
| **Evaluation stuck pending** | The learner sees "reviewing…" forever | `GET …/evaluations` shows `status: pending`; no `evaluations` diag line follows | The server probably restarted mid-evaluation. Request the evaluation again (`POST …/evaluations {draft_rev}`): the stale pending one becomes `failed (interrupted)` and a new one starts. With `WS5_MODULES=real`, check `ANTHROPIC_API_KEY`: a missing key gives `failed` (`module_error`) quickly, never `uncertain`. |
| **Evaluation failed** | The commit says `evaluation_required` (`details.reason: evaluation_failed`) | The evaluation has `status: failed` and `error_code`; `failing_components` contains `evaluations` | Re-evaluate. If it repeats with the real module, switch to the stub to keep the demo going and report the evaluation ID to WS5. |
| **Commit blocked** | `409` from `POST …/commit` | `error.code` + `error.details.policy_code` (see API doc §6) | `evaluation_required`: evaluate the current draft. `evaluation_pending`: wait for `evaluation.updated`. `evaluation_stale` / `evaluation_stale`: the draft changed, so evaluate again. `evaluation_stale` / `knowledge_changed`: the pinned knowledge was revised or revoked, so `POST …/pin`, then evaluate again. `commit_blocked` / `blocked_by_outcome`: the tutor intervened, so edit the draft (or, for `uncertain`, commit with `escalated: true`). `commit_blocked` / `already_committed`: it is already saved; `GET …/commit`. |
| **Newcomer session refused** | `POST /api/sessions {role:"newcomer"}` → `409` | `error.code`: `no_confirmed_knowledge` (with `details.excluded[].reason`) or `case_not_permitted` | No eligible knowledge yet: confirm a teach-back first. In a fixture-only demo, add `?allow_fixture_knowledge=1`, which the session records. `case_not_permitted`: that case was shown to the expert; pick an unseen one or omit `case_id`. |
| **SSE client disconnected** | The UI stops updating | `stream` diag lines: `open` and `close` with `duration_ms` per session | EventSource reconnects by itself with `Last-Event-ID`, and the server replays exactly the missed events. After a long gap, re-GET the resources. |
| **Access denied** | Every API call → `401 unauthorized` | `/api/health.access_token_required: true` | Send `Authorization: Bearer <token>`, or open `/api/access?token=<token>` once in the browser. Wrong token: compare with `BACKEND_ACCESS_TOKEN` in the server's env. |
| **A record "came back" after deletion** | It should not: late retries get `410 gone` (deleted) or `202 dropped_off_record` (off the record) | Tombstones in `knowledge/tombstones/`; `record.deleted` / `entry.revoked` on SSE | If a client keeps retrying a deleted ID, it must stop. `410` is final. |

**Transient processing while off the record (open team decision).** WS6 implements "not persisted, not forwarded to modules". Off-record writes are answered `202 dropped_off_record` before anything is written, and nothing reaches synthesis or the tutor. Whether WS2/WS3 may process off-record audio or frames transiently on the device is their decision.
