# Research / decisions — Sprint 4

1. **Exclusion point** — Decision: drop in the reducer at ingestion (state-based and time-based), plus a server-side snapshot validator that refuses any off-record record or content timestamped inside an off-record segment. Rationale: "dropped in memory, not flagged"; the validator is defence in depth. Alternative: filter at save time (rejected: draft builder and gap selector would still see it).
2. **Trigger utterance** — Decision: when going off record by agent tool or phrase, the latest user line that contains an off-record phrase (within 30 s) and every line after it are removed; the segment starts at that line. Without a phrase match (agent paraphrase), only the latest user line (if < 30 s old) is removed. Rationale: "off the record, X" is often one utterance and is transcribed before the tool call.
3. **Phrase detection** — Decision: the client also detects "off the record"/"stop recording" (→ off) and "back on the record"/"resume recording" (→ on) in final user lines. The "back on" line itself is dropped (it may carry trailing off-record words). Agent tool is idempotent so the agent still acknowledges.
4. **Capture events** — An event with `record_state: off_record` switches the session off (trigger `capture_event`) and is itself dropped. A later on-record capture event ends only a segment that a capture event started.
5. **Mute** — `useConversationInput().setMuted(true)` while off record is a console option, default off: a muted expert cannot say "back on the record". `sendUserActivity()` every 4 s while off record keeps the turn timeout from prompting the agent. DOCUMENTED-ONLY in voice.
6. **ElevenLabs deletion** — `conversations.delete(id)` (VERIFIED LIVE in Sprint 0). Only for ended sessions with ≥ 1 off-record segment, only ids stored in that session's `session.json`. 404 = `not_found`. Triggered by console button, or automatically after the final save when "delete at end" is ticked (default on). No ZRM / record_voice / retention_days changes on the shared agent (override; ZRM disables `conversations.get` and restricts LLMs).
7. **Strike** — keep the exchange as an id shell (answer_lines emptied) so references validate; record a `Strike` with superseded revisions and invalidated confirmations; redact derived AI text in place (revisions are rewritten only for ids a strike supersedes — the store's immutability check allows exactly that). Phase `confirmed` → `teach_back` (trigger `strike`), a fresh teach-back exchange is opened when the latest revision is still valid; otherwise `propose_draft` is allowed after a strike.
8. **Completion** — derived on every save of an ended session; `completed` ⇔ phase `confirmed` and a valid confirmation of the latest revision. Removed again on resume.
9. **Schema version** — session records `ws3.v1`; pointing events stay `ws3.v0` (WS2 contract unchanged).
10. **Resume** — console "Resume session" after an unconfirmed end; next connect reopens the same session id in the phase before the end, appends the new conversation id, sends `[RESUME]` summary (ids, channels, phase, open gaps, revision status; no expert words).
