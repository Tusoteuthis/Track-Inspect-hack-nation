# Finger pointing detector

User asked for a finger pointing detector running on a local model. Each analysed frame (glasses, iPhone camera or test photo) must report whether a hand is pointing with its index finger, the direction within the image and the fingertip position. Detection stays on the iPhone, shares the existing bounded analysis slot (one request in flight, about 1.3 analyses per second) and adds no download or dependency. It must be presented as a gesture heuristic, not as knowledge of what is being pointed at. The text summary sent to the voice agent may mention it only under the existing opt-in.

Plan: Apple Vision's on-device hand-pose model (`VNDetectHumanHandPoseRequest`, up to two hands) runs in the same `perform` call as the classifier inside `LocalAnalysisService`. SDK-free rule in `PointingDetector`: index finger within about 45° of straight and reaching away from the wrist, every visible other finger shorter than 0.7× the index reach; thumb ignored; joints below 0.3 confidence are dropped and occluded fingers are not held against the gesture. Geometry is aspect-corrected; direction is one of eight image-space sectors. `AnalysisResult.pointing` carries the result; the dashboard shows a pointing row and a ring on the fingertip in the preview. No privacy or architecture exceptions.

Completed: implementation, dashboard row and preview marker, agent-context sentence, `PointingTests` (rule geometry, aspect handling, real hand-pose request on a blank image, context wording). Regenerated Xcode project. 72 unit tests passed on the iPhone 16 simulator. UI suite not run. Not verified: detection on an actual hand — no hand image fixture is bundled and nothing was run on a phone or glasses, so accuracy, the 0.7/45° thresholds, egocentric (first-person) hands, gloves and latency are untested and remain a hardware gate. The marker updates at the analysis rate, so it lags a moving hand in live video.

## Target and annotated screenshot

User then asked for a model that reports the target, and a screenshot of the target with the pointing painted on and a box around the target. Everything stays on device and nothing is written to disk by the app.

Plan: when a pointing finger is found, Apple Vision's objectness saliency model (`VNGenerateObjectnessBasedSaliencyImageRequest`) proposes object boxes; `PointingDetector.target` picks the box the finger's ray enters first, skipping any box that contains the fingertip (the hand). Without a hit the target is a square ahead of the fingertip, flagged as not salient. The boxed region is classified with the existing classifier (general Vision labels, or `InspectionClassifier` when bundled) through `regionOfInterest`; the top label is the reported target. `PointingSnapshot` paints the box, finger line, fingertip ring, dashed aim line and label onto the frame. The ViewModel keeps the latest capture in memory (cleared on the next run, next photo or backgrounding); the dashboard shows it in a "Pointing target" panel with a user-initiated share button, and the live preview also draws the box.

Completed: implementation and ten `PointingTests`, all passing on the iPhone 16 simulator (ray/box selection, fallback square, real region classification and painting on a generated image, capture lifecycle). Not verified: the saliency model cannot create an inference context on the simulator, so it is compiled out there and only the fallback box ran; saliency, real hands and real targets have never been exercised and remain a hardware gate. Target labels are general image classifications of a crop, not object detection or defect recognition. In the same test run three lifecycle tests (`LifecycleTests`, `PrivacyTimingTests`, `UnpairTests`) failed; they exercise a concurrent, unrelated change to `startVoice` (glasses video restart around voice start) made outside this feature.

## Cloud description through Passiv, forwarded to the voice agent

User asked to send the screenshot to an LLM, using obachan's Passiv gateway for now, and to send the resulting text to the voice agent. This uploads an image, which Principle II forbade; the constitution is amended to 1.1.0 with a narrow, opt-in exception for the annotated pointing screenshot only.

Plan: `TargetDescriptionService` protocol; `PassivVisionService` posts the annotated screenshot (downscaled to 1024 px) to the gateway's OpenAI-compatible `/v1/chat/completions` with a short prompt and the local label as a hint. Host, model alias and key come from xcconfig through `Info.plist` (`PASSIV_GATEWAY_HOST`, `PASSIV_MODEL`, `PASSIV_API_KEY`); without a key the service is absent and the toggle is disabled. The ViewModel uploads only while "Describe pointing targets with a cloud model" is on (off by default, reset on backgrounding), one request in flight, at most one per 10 seconds per run; the panel keeps the frame that was sent so picture and text match. When the description arrives it is shown in the panel and, if a voice call is active, sent to the agent as contextual text marked unverified. This is independent of "Share local findings".

Completed: implementation and six `PassivTests` passing on the simulator (request shape, response parsing, downscaling, no describer without a key, nothing uploaded without opt-in, description reaching panel and voice agent, reset on backgrounding). Not verified: no request has been sent to a real gateway — no key is configured, the default host `gateway.mezzanin.eu` and alias `claude-sonnet` are taken from obachan's documentation examples and unconfirmed, and the 10-second spacing within a live stream has no test. The key ships inside the app bundle and can be extracted from it; acceptable only for prototype builds with a narrowly scoped virtual key, and a backend-issued short-lived credential is the proper replacement. The same three unrelated lifecycle tests still fail (82 run, 79 pass).

Key provisioned 2026-10-04: `obachan passiv mint-key --env prod --app trackinspect-ios --model claude-sonnet --gateway-url https://gateway.mezzanin.eu/v1 --max-budget 25`. Alias `obachan-prod-trackinspect-ios`, stored in OpenBao at `obachan/prod/trackinspect-ios.llm_gateway_api_key` and copied into the ignored `Secrets.xcconfig`. A direct request with that key and a small test image to `claude-sonnet` returned HTTP 200 with a correct answer, which confirms host, alias, key and image input. The app itself has still not made a request: no build with the key has been run.

## First device run and follow-up (build 21)

Build 19 on the iPhone 16 Pro Max detected a real pointing hand, boxed a target, got a Passiv description and showed it. Owner feedback: the description must reach the agent as text whenever they point, and cloud description should be the default.

Changed: the description is sent with the SDK's `sendMessage` (`VoiceService.sendText`), which the agent answers, instead of a silent contextual update; it is prefixed as an automatic camera message. A new pointing gesture is described at once (3-second floor); continuous pointing every 10 seconds. The switch is on by default and no longer reset on backgrounding (constitution 1.2.0). The fallback box now starts at the fingertip instead of one box-length ahead, and the prompt asks for plain text about what lies at the fingertip, treating the box as a rough guess — in the device screenshot the box sat above the chart the finger was touching. 83 unit tests passed. Build 0.1.0 (21) legacy installed and launched. Not verified: whether the agent actually answers the text message, the per-gesture timing on device, and saliency-based boxes (the one device frame seen used the fallback).

## Build 22: only deliberate pointing; agent reply

Device run of build 21: descriptions reached the agent as user text (visible in the transcript) but fired while the owner was merely tapping the phone, and the agent did not answer. Changed: in live video a finger must hold still (tip within 0.1 of the frame) for two consecutive analysed frames before anything is uploaded; photos are exempt. The Passiv prompt returns `NONE` for hands that are tapping, typing on or holding a device; such frames are shown as "Not a deliberate point" and never sent to the agent. Not verified on device. The agent's own ElevenLabs prompt ("stay quiet most of the time") is outside this app and may still keep it silent.

## Build 23: backend integration, description visible to the Expert agent

Owner asked to integrate the project backend (`web/` of `Tusoteuthis/Track-Inspect-hack-nation`, `voice` branch) and confirmed the Expert agent should see the vision description.

App: the description now reaches the agent as the contextual line the Expert prompt already defines, `[POINTING_EVENT] event_id=… mapping_status=resolved channel=unknown trace=unknown record_state=on_record source=live. …`, followed by a labelled `[VISUAL_CONTEXT]` machine guess (`PointingEventLine`); the first-person user message of build 22 and `VoiceService.sendText` are removed. `BackendPointingRecorder` stores each described point through the backend's existing ingest: create and start an expert session on the first event, upload frame plus annotated frame as an asset, then PUT the pointing event with the same `event_id`, the target box and `target_description`; the session is ended when voice stops or the app backgrounds. Host and token come from xcconfig (`BACKEND_HOST`, `BACKEND_ACCESS_TOKEN`); without a token the recorder is absent. The panel shows whether the event was saved. Constitution 1.3.0 covers the extra upload.

Backend (local branch `worktree-pointing-description` off `origin/voice`, commit 55703da, not pushed): optional `target_description` on `PointingEvent` and its zod schema; `formatPointingEventUpdate` appends the same `[VISUAL_CONTEXT]` text; the Expert system prompt gains one rule for it. Typecheck clean, 1,992 web tests passed.

Verified: 89 unit tests on the simulator, including the recorder run against that branch's backend started locally — both events were read back from disk with `target_description`, rewritten image refs and the session `ended`. Build 0.1.0 (23) legacy installed and launched. Not verified: the deployed backend (no token in the build, and it does not have the new field until the branch is merged and deployed; the old schema silently drops it), whether the live ElevenLabs agent asks about a point (its prompt has not been re-synced, and the app sends no `[CONTROL]` pause nudge as the web client does), and JPEGs with a rotated EXIF orientation.
